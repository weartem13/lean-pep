# Reproducibility and identities

`SOURCE_MANIFEST.json` identifies the maintained code, required case/fixture data, tests, entry scripts, toolchain, requirements and documentation. It includes retained research evidence under `data/paper`, whose directory name does not designate manuscript content. `PUBLIC_MANIFEST.json` identifies the same exported payload. The manuscript and local publication/editing metadata are excluded from both payloads; the two generated manifests themselves are not self-hashed. Both sort POSIX relative path strings and hash explicit byte entries. Neither is a cryptographic attestation of a solver execution.

The accepted pre-migration source is `sha256:e43a0018cd7dd8d202361abcea8fcbbda1db7981bf25ec5e36c317116b1f429c`; its original ZIP and manifests remain privately preserved without relabeling. The fixed eight-configuration batch and prior execution costs remain attached to that source. Current layout checks have separate command logs and a new source identity. A layout rebuild is not a rerun of the eight solves.

The export uses an explicit root allowlist and rejects symlinks/caches/private paths. It excludes .git, environments, dependency packages, manuscript inputs and paper packages, old editing reports and previous drafts. The specific local-only publication records are listed in `scripts/export.py`; useful declaration/evidence maps are retained in `docs/evidence`. A new validation root starts without project .olean/.ilean/.lake/build; locked external dependencies may be acquired from official upstreams or copied through the original pin/clean cache guard. Core, aggregate, unaggregated modules, every maintenance test/smoke/Replay and offline verify/recover are recorded against that new root.

The public numerical evidence is self-contained under `data/paper`: all batch outcomes and the reference R02 input are local files, with no invented download URL. `data/paper/evidence-index.json` maps retained original hashes to public paths and identifies path-redacted derivatives. Repeated B06 is associated with B05, not counted as a second recovery/Lean execution.

The [declaration/evidence map](evidence/claim-evidence.md) resolves source and execution paths within this code distribution. A commit SHA belongs in an external release receipt after the commit exists, avoiding a self-reference. If documentation or export logic changes, targeted tests and a fresh-export quick check validate that new snapshot; old full-suite counts remain historical evidence.

See the separately delivered local preparation report and validation-log package for exact current command exits. Setup and full checks retain failure output and stop on errors. Platform/runtime/caching observations have their own scope; reuse of official binary dependencies is not a full dependency-source cold build. No remote publication or arXiv submission is performed by these tools.
