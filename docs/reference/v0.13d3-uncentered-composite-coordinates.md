## The coordinate boundary

This is a fixed, normalized, explicit uncentered leaf convention, NOT automatic
parsing of arbitrary PEPit leaf order. For T=n+1>0, keep the same 2T+3 value slots
as D2. The basis changes from

  Y = [x_star,x0,g_star,g0,...,gT,s1,...,sT]

to

  Z = [x0-x_star,g_star,g0,...,gT,s1,...,sT].

There are 2T+4 native vectors and 2T+3 centered vectors. Source normalization is
L=step=radiusSquared=1; the existing actual-function bridge supplies physical
L>0,R>=0 scaling. Values f_star and h_star are NOT forced to zero. The nonsmooth
star oracle remains -g_star; no oracle at x0 is invented.

Let C have first row [-1,1,0,...] and subsequent identity rows selecting the
remaining native coordinates. Let J have a zero first row and identity below.
Then Z=C Y and J Z=[0,Z...]. C J=I, but J C is NOT I: translation has been removed.
D3 checks BOTH submitted rectangular matrices against these independently
specified maps. It never infers a coordinate map from a hash or dimensions alone.

## Coordinate algebra in Lean

`GramPEP.OriginCoordinates` defines coefficient restriction and lifting,
including the two different lifts for a point and an oracle:

  point coefficient: e_origin + C^T v
  oracle coefficient: C^T v.

For a scalar Gram coefficient matrix S, lifting is C^T S C, including both cross
blocks. Restriction of native coefficients B is J^T B J, the bottom-right block.
The new general lemmas connect these specialized operations with exact finite
matrix sums, prove restriction after lifting is identity, and establish exact
real evaluation in the zero-origin section. `zeroOriginGramR_psd` shows that
zero-padding centered Gram data preserves PSD.

The PRIMAL transformation has the opposite role: G_centered=C G_native C^T.
It is not generally the bottom-right block of G_native. D3 does NOT implement
an arbitrary-native-primal importer or a primal-to-actual lower-witness lift.

## Why round-trip checking is mandatory

Merely setting x_star=0 can erase a malicious term such as ||x_star||^2 or an
origin-gradient cross term. A correct centered model is not by itself evidence
that the complete native formulation was correct.

The source audit checks, without sorting or truncation:

* the entire native mathematical header and both coordinate matrices;
* every native sample equals the appropriate point/oracle lift of its restriction;
* every native constraint and the objective equal their FULL lifted restrictions;
* the restricted source passes the unchanged D2 source checker.

`checkSourceQ_eq_expected` proves acceptance iff the entire submitted native
source equals `expectedSourceQ n`. This expected source is built only from the
old C2 Lean compiler and the specified coordinate lift. The producer does not
supply it. `expectedSource_check` holds for arbitrary n, not just the fixtures.

All ordered smooth and nonsmooth pairs, self pairs and the radius row remain in
D2 order. There is no change of inequality sense, row permutation or value order.

## Certificates and theorem-level binding

`centeredUpperQ s c` restricts the SUBMITTED native certificate. It preserves its
bound, every multiplier, every index, and all implicit terms. Indices are
transported using list-map length equality, not default lookup. Its dual matrix
is J^T S_native J; factors retain weights and use vectors J^T w. There is no new
factor synthesis or repair during this transformation. A lemma proves that the
sum of restricted weighted factors is exactly the restricted original factor sum.

`checkBoundQ` requires all of:

1. the native source audit;
2. the OLD native upper-certificate checker;
3. empty implicit single-function interpolation and native objective binding;
4. the unchanged D2 joint checker on the restricted source and certificate.

Both complete certificate checks are deliberate. We do not claim a new universal
completeness theorem saying that every accepted native certificate necessarily
passes the transformed checker. Acceptance soundness is sufficient for this
version. A malformed native dual matrix cannot be hidden in the erased origin
coordinate even if its restriction happens to yield an accepted certificate.

`checked_certificate` returns an accepted certificate of the original C2 model,
with the SAME submitted bound and objective. The actual-function application
module calls D2 directly; it does not reconstruct a new mathematical algorithm.
For arbitrary positive horizon the bound is L R^2 * c.bound. The three-step
fixture yields the already-known L R^2/12 upper bound, not a new rate.

## Exact input, generation, and examples

New format: `leanpep-uncentered-pg-source-v1`.

`tools/import_proximal_gradient_coordinates.py` uses exact {num,den} scalars,
rejects floats, decimal strings, duplicate/unknown fields, dimension errors and
out-of-range indices. It emits only the submitted typed native data, not an
acceptance proof. Its optional centered JSON output uses the unchanged D2 format.
The source matrices remain independent targets, not definitions from their factors.

Example:

```bash
python3 tools/import_proximal_gradient_coordinates.py \
  data/fixtures/composite_coordinates/pg_three_step.json \
  --expected-steps 3 \
  --lean /tmp/PGNativeThree.lean \
  --report /tmp/PGNativeThree_report.json \
  --centered-json /tmp/PGNativeThree_centered.json \
  --namespace LeanPEP.Imported.PGNativeThree
```

The three normal examples are DETERMINISTIC REGRESSION FIXTURES, not live captures.
Fixture creation builds raw sample vectors directly and compiles the native
component pairs. It computes the independent dual matrix from the certificate
residual before using D1 factor synthesis. Normal regeneration reads committed
inputs and never regenerates a damaged input into a correct expected snapshot.

Independent Lean regression scripts include hidden-origin constraints, polluted
point-origin coefficients, wrong map signs, a wrong section, a native-only dual
error, and the mandatory empty implicit-interpolation guard. In several cases
the centered check intentionally passes while the full native check rejects.

## Explicit non-goals

No live PEPit/SDP invocation or producer identity is authenticated here. There is
no JSON-parser correctness theorem, float reconstruction, arbitrary permutation,
non-unit source scaling, PEPit epigraph/extra-row handling, extended-real h,
composite primal completeness, or new lower witness. The supported leaf
convention is not a claim that arbitrary current PEPit output has this order.
Old core checkers, mathematical modules, schemas and importers are unchanged.
