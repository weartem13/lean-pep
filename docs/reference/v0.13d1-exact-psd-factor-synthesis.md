## What this slice adds

`tools/synthesize_psd_factors.py` accepts an exact rational square matrix and
returns either (i) nonnegative weighted rational rank-one factors, (ii) an
original-coordinate rational vector with negative quadratic value, or (iii)
an explicit asymmetry. The same function processes primal and dual matrices.
Zero dimension is supported by the standalone matrix interface. The existing
bundle schema still requires nonempty point/basis labels, without modification.

Positive output has the OLD `PSDFactorCertQ` representation. The target matrix
is emitted independently, never defined as `factorGramQ factors`. All entries
and signs are checked by the original `checkPSDFactorQ`; its old rational and
real soundness theorems provide the mathematical meaning.

This is not a new convergence rate, a live solver capture, an algorithm for
rounding nearly PSD matrices, or a proof of interpolation completeness. It is
also not a Lean formalization of the producer's general correctness or
completeness. Every emitted instance must be checked independently.

## Exact algorithm

For a symmetric matrix A, maintain

    A = sum_j d_j v_j v_j^T + S,

where S has zero rows and columns at all eliminated pivot positions. Select a
strictly positive diagonal entry d=S[p,p] in the requested priority order;
set v[i]=S[i,p]/d on active coordinates, zero on previous pivots, and replace

    S <- S - d v v^T.

Each v[p]=1. There are at most n positive pivots. If the remaining block is
zero, the decomposition is complete. All arithmetic is fractions.Fraction;
there are no square roots, spectral approximations, tolerances, diagonal
shifts, or symmetrization. Priority permutations are checked and all output
vectors remain in the ORIGINAL matrix coordinate order.

If S[i,i]<0, take its coordinate vector. If S[i,i]=0 but S[i,j]!=0, take

    w[j]=1, w[i]=-(S[j,j]+1)/(2*S[i,j]), all other entries zero.

Then w^T S w=-1. Lift this vector BACKWARDS through previous pivots by setting

    w[p] = -sum_(i != p) v[i] w[i].

This annihilates every earlier square, hence w^T A w retains the negative
Schur value. A negative pivot by itself is not emitted as an original-coordinate
witness. The implementation independently recomputes the final quadratic form.

Asymmetry is a distinct failure. It need not produce a negative quadratic
vector; it violates the symmetry component of the project's PSD predicate.

An independent full-entry check follows successful synthesis. With exact
unbounded arithmetic the procedure covers symmetric rational PSD matrices,
including singular ones. This algorithmic argument is documented here, not
claimed as a universal Lean correctness theorem. Rational coefficient bit
sizes and costs can grow; no uniform performance or optimality claim is made.

## Example

For A=[[2,1],[1,3]], the producer returns

    2 * [1,1/2] [1,1/2]^T + (5/2) * [0,1] [0,1]^T.

A Cholesky representation would involve square roots, but the weighted
rational representation does not. For A=[[1,2],[2,1]], elimination returns
w=[-2,1], with w^T A w=-3. A tiny exact negative entry is never rounded to zero.

## Original checker integration

New `GramPEP/FactorReplacement.lean` provides theorems for negative witnesses
and a factor-replacement combinator. `UpperCertQ.withDualFactor` changes only
the factor representation: bound, objective, ordered multipliers, dual matrix
and certificateRhsExprQ remain unchanged. Given original upper acceptance and
new PSD-factor acceptance, `checkUpperCertQ_withDualFactor` derives acceptance
by the SAME old upper checker.

New generated `Imported/PSDSynthesized.lean` contains 15 independent matrices:
9 PSD cases, 5 negative-quadratic cases and 1 asymmetry case. It includes empty,
zero, singular/permuted, nonsquare-root rational, tiny-negative, and GD/PG
regressions. Positive proofs use `decide +kernel` followed by the old soundness
theorems. Negative proofs use exact witness evaluation, with no new negative
checker. Asymmetry is proved by an unequal pair of entries.

`Imported/GramOneStepResynthesized.lean` is produced using the old exact Gram
importer in data-only mode. The JSON retains its input `expect` annotation;
that annotation is not an acceptance result and is not used as a premise.
`PSDSynthesisRegression.lean` independently proves model, primal, objective and
dual-matrix equality with the old GD fixture, full bundle acceptance and real
attainment 1/6. It does not invoke any of the old imported native-decided
acceptance theorems. Wrong factors, negative weights and a wrong bound have
explicit rejection regressions.

`ActualFunction/PSDSynthesisApplications.lean` binds the one/two-step PG matrix
fixtures to the original `upperCertQ 0/1` dual matrices, by the old exact entry
checker, before replacing factors. It derives original upper-checker acceptance
and a two-step actual analytic bound LR^2/8 via the C5 minimizer interface.
The generic wrapper accepts any checked alternative factor list at any horizon.
These are alternate representations of the OLD certificate, not independently
rediscovered multipliers or new optimality constants.

GD's original dual has 3 displayed factors; synthesis returns 2. PG T=1,2 have
4,7 displayed factors (including zeros); synthesis returns 3,5. These are exact
representation counts, not a new claim about optimal PEP values. The PG primal
matrix fixture is matrix-level only; D1 does not implement a composite external
bundle schema or claim a primal-to-actual lift for it.

## JSON and CLI

Standalone input uses a new, matrix-only envelope. Every scalar is a strict
`{"num": integer, "den": positive_integer}` object. For example:

    {
      "format": "leanpep-rational-matrix-v1",
      "dimension": 1,
      "matrix": [[{"num": 2, "den": 1}]]
    }

    python3 tools/synthesize_psd_factors.py matrix my_matrix.json \
      --output my_matrix_report.json --lean MyMatrix.lean \
      --namespace LeanPEP.Imported.MyMatrix

For existing exact Gram bundles:

    python3 tools/synthesize_psd_factors.py bundle \
      data/fixtures/gram_external/one_step_exact.json \
      --output /tmp/gd_refactored.json --report /tmp/gd_factor_report.json \
      --lean /tmp/GDRefactored.lean --namespace LeanPEP.Imported.GDRefactored

Only these four fields may change in bundle mode:

    primal.gram_factor
    upper.dual_factor
    declared.primal_factor_count
    declared.dual_factor_count

Old factor hints are shape-validated but not read by the synthesis algorithm;
they can be empty lists with zero counts. All other fields, especially matrices,
values, model coefficients, ordering, multipliers, bounds and expect annotations,
are preserved. Malformed syntax is rejected; unrelated invalid metadata or bounds
are not repaired. Both matrices must succeed before any replacement bundle is
emitted. Reports explicitly say full bundle acceptance and formulation auditing
have NOT been performed. Generated bundle Lean code is data-only: consumers
must invoke the old full checker separately.

Exit status: 0 for successful PSD matrix/both bundle matrices; 1 for exact
matrix failure; 2 for input/I/O errors. Matrix failures can emit a negative Lean
witness. Bundle failures emit only the report and leave any pre-existing bundle
or Lean output untouched; callers MUST check the exit status. Paths must be
distinct. Writes are atomic per file, not a multi-file transaction.

The producer does not change raw versus reconstructed semantics: it operates on
an already exact matrix. It cannot turn a raw indefinite matrix into a nearby
PSD one, and it must not be used to claim that an original floating solution
passed an exact audit. No external solver or new plugin is required for D1.

## Remaining next slices

It does NOT close multi-algorithm live source capture, composite source-schema
validation, rational reconstruction of solver outputs or interpolation
completeness. The next platform slice should bind captured external formulations
to the existing Lean expected profiles, retaining raw/reconstructed separation.
