## Generic two-sequence compiler

`Momentum.ScheduleQ` contains arbitrary rational `step` and `momentum`
schedules.  The source semantics are

```text
x_0 = y_0 = initial
x_(k+1) = y_k - step(k) g_k
y_(k+1) = x_(k+1) + momentum(k) (x_(k+1) - x_k),
```

where `g_k` is sampled at `y_k`.  State and query are distinct fields of one
recursive coefficient state, not two unrelated hand-written coefficient tables.
If `a(k,j)` and `b(k,j)` are their cumulative gradient coefficients, then

```text
a(k+1,j) = b(k,j) + (if j = k then step(k) else 0)
b(k+1,j) = (1 + momentum(k)) a(k+1,j) - momentum(k) a(k,j).
```

`coefficientStateQ_causal` proves both coefficient rows vanish for `k <= j`,
for all horizons and arbitrary schedules.  This is a causality theorem,
NOT a convergence claim for arbitrary (possibly negative) schedule entries.
`stateAffineQ_succ` and `queryAffineQ_succ` establish the source updates as
identities in the existing `GradAffineQ` language.  Their scalar evaluation
lemmas state the corresponding exact real recurrences.

`queryProfileQ N` lowers queries to the existing `FixedStepFirstOrder.ProfileQ`.
`outputProfileQ N` instead uses queries before index `N` and state `x_N` at
the terminal index.  It does not modify the last momentum coefficient or
mislabel an extrapolated query as an output.  At `N=0` it contains the initial
state.  The terminal gradient is sampled only for interpolation and appears
in no position coefficient.

`outputPEPProfileQ`, `outputModelQ`, and `outputObjectiveQ` reuse the A2
normalization, objective, point ordering, basis ordering, and `compileModelQ`.
The compiled positions before/at the terminal index are proved equal to the
appropriate query/state affine forms; causality is preserved in Gram coordinates.

## Four-step rational Nesterov pilot

The schedule is

```text
step(k) = 1
momentum(k) = k / (k + 3),   k = 0,1,2,...
```

This is the rational simplified fast-gradient variant, not the variant with
square-root parameter updates.  The source reference for this exact zero-based
convention is PEPit's executable loop in
`accelerated_gradient_convex_simplified.py` (the loop uses `i/(i+3)`).
The displayed algorithm in that documentation uses a different index convention;
this implementation follows the loop explicitly, not an inferred reconciliation.

Reference (consulted 2026-09-06):
https://pepit.readthedocs.io/en/latest/_modules/PEPit/data/fixtures/unconstrained_convex_minimization/accelerated_gradient_convex_simplified.html

No PEPit execution, live capture, or solver run is claimed for this slice.
The exact pilot certificate was derived symbolically and checked independently
with rational arithmetic.  No new rate-discovery or priority claim is made.

The four-step sample order is

```text
star, y_0, y_1, y_2, y_3, x_4
```

and the basis order is

```text
x_0 - star, g(y_0), g(y_1), g(y_2), g(y_3), g(x_4).
```

The compiler output is proved to have positions

```text
y_0 = x_0
y_1 = x_0 - g_0
y_2 = x_0 - g_0 - (5/4) g_1
y_3 = x_0 - g_0 - (27/20) g_1 - (7/5) g_2
x_4 = x_0 - g_0 - (27/20) g_1 - (7/5) g_2 - g_3.
```

Thus `y_3 - y_2 = -(1/10) g_1 - (7/5) g_2`.  This is genuine historical
mixing, not merely a different step size multiplying the current gradient.
The final unused query differs from `x_4`: its cumulative coefficient on
`g_3` is `3/2`, whereas the output state's coefficient is `1`.

## Exact finite certificate and matching primal

The submitted `pilotUpperCertQ : UpperCertQ pilotModelQ` has bound `1/21`,
9 interpolation terms, the compiled radius assumption with multiplier `1/21`,
and 11 positive rational rank-one dual factors.  One factor is a centering
square; the other ten are differences of pairs of sampled gradients.  The
dual matrix is reconstructed by the existing `factorGramQ`.

The exact target identity is

```text
1/21 - (f(x_4)-f_star)
  = sum interpolationWeight * orderedSlack
    + (1/21) * (1 - G_00)
    + <dualMatrix, G>.
```

`pilotUpperCertQ_check` submits this object to the unchanged general Gram
checker.  The closed computations use `decide +kernel`, not `native_decide`.
The `+kernel` mode was checked against the pinned Lean 4.31.0 tactic source;
it checks the reduction in the kernel rather than adding a native-evaluation
axiom.  This choice is not a claim that these new files have already compiled.
`pilot_upper` reuses the existing real soundness theorem.

The matching primal is the rank-one Gram matrix `v v^T` with

```text
v = (1, 2/21, 2/21, 2/21, 2/21, 2/21).
values = (0, 40/441, 4/49, 31/441, 25/441, 1/21).
```

Its positions and gradients are taken directly from the compiled model.
The existing primal PSD, all-ordered-pair interpolation, and assumption
checkers establish its exact feasibility.  The rational-to-real bridges
then supply an attaining real finite Gram datum.

`pilot_finite_tight` states

```text
IsGreatest pilotFiniteValues (1/21 : Real).
```

This is finite Gram tightness.  It is not a proof of interpolation completeness,
a generic actual-function lift, an arbitrary-N accelerated rate, or an OGM
result.  Although the finite values match a Huber sample, no new analytic
witness theorem is asserted in this slice.
