## Reusable oracle-agreement lemma

`MomentumOracleAgreement.lean` extends namespace `MomentumActual` without
modifying its existing source.  It proves that if `g'` and `g` agree at the
reference run's query points for every `k < N`, then the state AND query
sequences agree through `k = N`:

```text
g'(query s g x0 k) = g(query s g x0 k), k < N
  => state s g' x0 k = state s g x0 k, k <= N
  => query s g' x0 k = query s g x0 k, k <= N.
```

The proof first transports the ordinary `IsRun` equations, then invokes the
existing `eq_of_isRun`.  It is independent of smoothness, positive schedule
coefficients, finite Gram feasibility, and certificates.  The selected
`outputPoints` also agree, including the final STATE.

No agreement at the terminal gradient observation is required.  Therefore the
lemma does NOT assert equality of the two complete Gram data.  In particular,
agreement only on state points cannot replace agreement on the queried points.

Public interfaces:

- `isRun_of_oracle_eq_on_queries`
- `eq_of_oracle_eq_on_queries`
- `outputPoints_eq_of_oracle_eq_on_queries`

## Explicit actual function

`NesterovPilotWitness.lean` uses exactly the existing one-sided Huber convention:

```text
a = 2/21
f(x) = x^2/2                         if x <= a
       a*x - a^2/2                  if x > a
g(x) = min(x,a).
```

`analytic`, `firstOrder`, `witnessFunction_zero`, `witnessGradient_zero`, and
`zero_isGlobalMin` reuse the preexisting general-threshold Huber theorems.
Here `IsOneSmoothConvexAnalytic` means the project's analysis-facing contract:
actual gradient everywhere, global convexity, and a 1-Lipschitz gradient.  It
is not a requirement of power-series analyticity.

The initial point is 1; the stationary global minimizer is 0; the squared
initial radius is exactly 1.  The auxiliary constant-field reference run is
NOT itself claimed to have a stationary minimizer: its field at zero is a,
whereas the true Huber gradient at zero is zero.

## Actual state and query trajectory

The schedule is unchanged from B1 and B2:

```text
x_0 = y_0 = 1
x_(k+1) = y_k - g(y_k)
y_(k+1) = x_(k+1) + k/(k+3) * (x_(k+1) - x_k).
```

`referenceState` and `referenceQuery` use the existing `MomentumActual`
recursion with the constant field a; they are not hand-written finite tables
or a substitute definition of the real run.  `reference_state_values` and
`reference_query_values` calculate:

| k | state x_k | query y_k |
|---|---|---|
| 0 | 1 | 1 |
| 1 | 19/21 | 19/21 |
| 2 | 17/21 | 11/14 |
| 3 | 29/42 | 9/14 |
| 4 | 23/42 | 10/21 |

`threshold_le_referenceQuery` proves the branch condition for k <= 4.
`gradient_referenceQuery` discharges the oracle-agreement premise, and
`actual_trajectory` identifies BOTH actual Huber sequences through step four.
Only queries k < 4 drive updates.  No agreement beyond this finite horizon is
claimed.

The actual final objective is:

```text
f(x_4)-f(0) = (2/21)*(23/42) - (2/21)^2/2 = 1/21.
```

The unused final query is different, and so is its value:

```text
x_4 = 23/42 != 10/21 = y_4
f(y_4)-f(0) = 2/49 != 1/21.
```

Public interfaces include `actual_trajectory`, `iterate_four`, `query_four`,
`terminal_state_ne_query`, `attains`, `final_query_gap`, `attains_of_isRun`,
and `normalized_analytic_lower_witness`.

## Actual tightness, not finite-primal inference

`oneDimensionalAnalyticValues` is defined using genuine f,g : Real -> Real,
a stationary point, squared radius at most 1, and the actual four-step
`NesterovPilotUpper.iterate`.  It contains no finite `DataR`, `CoreFeasible`,
Gram factor, or accepted-primal hypothesis.

`bound_mem_oneDimensionalAnalyticValues` uses the explicit Huber witness.
`oneDimensional_analytic_tight` combines that membership with B2's unchanged
`upper_analytic`, giving the source theorem:

```lean
IsGreatest oneDimensionalAnalyticValues ((1 : ℝ) / 21)
```

`analytic_upper_and_oneDimensional_tight` packages the dimension-independent
upper bound with this one-dimensional attainment.  There is no newly defined
set ranging over all universes/Hilbert spaces.

The lower-witness proof does not use B1 finite-primal feasibility or
interpolation completeness.  The independent Python regression additionally
checks that its actual samples have exactly B1's primal values and Gram
matrix, and that all weighted slacks and dual factors vanish.  Those numerical
comparisons are not new Lean data-equality theorems.

## Explicit limits and next slice

This is normalized L=1, radius=1, FOUR-step tightness for the rational schedule
k/(k+3).  It is not the square-root-parameter accelerated schedule, an
arbitrary-N tight rate, an actual-function interpolation-completeness theorem,
or a claim of a new rate in the optimization literature.  No live solver was
run, and no core or stable schema was changed.

A next mathematical slice can add generic momentum normalization for positive
L and nonnegative radius R, then combine it with a correspondingly scaled
Huber witness.  This requires a generic trajectory-scaling proof, not a second
Gram checker or new floating-point certificate.
