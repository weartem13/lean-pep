## Boundary and purpose

D1 checks factors of exact matrices. D2 additionally binds a submitted composite
formulation to the existing Lean-generated C2 proximal-gradient model. A valid
upper certificate of an unrelated or artificially strengthened problem must
not produce an upper theorem for the requested actual algorithm.

This version supports normalized, centered exact snapshots only:

- T = n+1 > 0, unit smoothness, unit step and squared radius bound 1;
- f is one-smooth convex, h is real-valued convex;
- value slots: f_star, f0,...,fT, h_star, h1,...,hT;
- basis: x0-x_star, g_star, g0,...,gT, s1,...,sT;
- smooth samples: star,x0,...,xT; nonsmooth samples: star,x1,...,xT;
- the nonsmooth star oracle is -g_star, not zero;
- all (T+2)^2 smooth ordered pairs, then (T+1)^2 nonsmooth pairs,
  including self pairs, followed by 1 - ||x0-x_star||^2 >= 0;
- symmetric Gram coefficient representation with all matrix entries compared;
- composite objective fT+hT-f_star-h_star.

This is NOT a PEPit-native leaf-coordinate adapter or a proof of any coordinate
conversion. The old one-step PEPit adapter and all old schemas remain unchanged.

## Lean implementation

`Adapters/ExactFormulation.lean` supplies an ordered list comparator with a
proof that acceptance is exactly equality. Both tail lengths are checked;
there is no zip truncation. It also transports UpperCertQ through a PROVED
ModelQ equality, preserving bound, objective, implicit terms and dual matrix,
and proves preservation of the ORIGINAL checkUpperCertQ result.

`Adapters/ProximalGradientSource.lean` defines the typed source. Its submitted
constraint list constructs the source ModelQ carrier; no expected constraint
is silently substituted before the local certificate check. The carrier's
position/gradient fields are zero, exactly as in the original composite
compiler. The independent expected data are built by the existing
smoothComponentQ, nonsmoothComponentQ, modelQ and objectiveQ.

`checkSourceQ_eq_true_iff` proves full source equality with expectedSourceQ n,
including header, class tags, sense, all sample coefficients, all ordered
constraint coefficients and the objective. `expectedSource_model` connects the
expected carrier to the old C2 model by reflexivity. `source_model_eq` and
`source_objective_eq` extract the mathematical binding.

`auditSourceQ` exposes five separate Boolean block diagnostics. The Python
report additionally enumerates individual mismatching field paths and exact
values; these Python diagnostics are untrusted and are not Lean theorems.

The combined check is the conjunction of FOUR distinct checks:

    source binding
    original checkUpperCertQ (against the source's own model)
    c.interpTerms = []
    c.objective = s.objective

`checked_certificate` converts combined acceptance to an accepted certificate
of the OLD expected model with the SAME submitted bound. Neither a matrix PSD
check nor a source-only check establishes this conclusion alone.

`ActualFunction/ProximalGradientSourceAudit.lean` then applies the unchanged C5
ordinary-minimizer and C4 physical scaling bridge. Its first-order theorem is
uniform in n and gives actual gap <= L R^2 * c.bound. It does not require the
submitted bound to equal a known closed-form rate. The analytic wrapper uses
the existing analytic-to-first-order bridge. The supplied three-step example
has bound 1/12 and yields gap <= L R^2 / 12. This is a new audited application
of an old numerical result, not a new rate or a new lower-bound theorem.

## Exact file format and CLI

New format: `leanpep-centered-pg-source-v1`. Root fields, all required:

    format, horizon, origin, source, upper

horizon is a strictly positive integer (not bool). origin has mode and
description; supported modes are deterministic_regression_fixture and
external_exact_snapshot. Origin is recorded, NOT authenticated.

source has header, smooth_samples, nonsmooth_samples, constraints, objective.
header has profile_id, coordinates, steps, value_count, basis_count,
smoothness, step_size, radius_squared, smooth_class, nonsmooth_class, sense,
basis_order, value_order, constraint_order. Row tags are {kind,i,j}, with kind
smoothPair/convexPair/radius and nullable natural indices. Samples have
value_index, position and oracle. Expressions have const, value_coeff and
full gram_coeff. Rational numbers use EXACT {num: integer, den: positive
integer} records. No binary float, decimal interpretation or rounding occurs.

upper uses the existing exact upper data fields: bound, objective,
interp_terms, assumption_terms, dual_matrix and dual_factor. Indices are
checked against the actually submitted source list. The empty implicit-term
condition is checked separately, not assumed by the structural parser.

Missing/unknown fields, duplicate JSON keys, invalid rational types, malformed
arrays, invalid indices and unsafe namespaces are rejected structurally.
Well-shaped but mathematically wrong candidates can still be emitted as Lean
data for an independent rejection test. The renderer never calls the Python
expected-profile mirror to repair submitted data and generates no acceptance
theorem. --require-diagnostic-pass is optional and means PYTHON DIAGNOSTICS,
not kernel validation. --expected-steps independently binds the caller's
requested horizon to the artifact horizon before emission.

Example (run at repository root):

```sh
python3 tools/import_proximal_gradient_source.py \
  data/fixtures/composite_source/pg_three_step.json \
  --expected-steps 3 \
  --lean /tmp/PGThreeSource.lean \
  --report /tmp/PGThreeSource_report.json \
  --namespace LeanPEP.Imported.PGThreeSource
```

Input and both outputs must resolve to distinct paths. Hashes identify the
provided JSON; they do not prove producer authenticity or parser correctness.
Lean certifies the EMITTED typed snapshot and its binding to the expected
problem, not a verified interpretation of arbitrary raw file bytes.

## Fixtures, D1 reuse and negative checks

The one-, two- and three-step inputs are deterministic exact regression
fixtures, not live solver output. They use known closed-form weights. Their
target dual matrices are computed BEFORE factor synthesis, as the target
expression minus weighted constraints; D1 synthesizes rational factors of
those fixed matrices. Normal regeneration READS the fixture inputs, instead
of regenerating or overwriting them from an expected model.

`Imported/CompositeSource.lean` contains data only; hand-written independent
checks in CompositeSourceRegression.lean invoke the source and original upper
checkers with `decide +kernel`. Concrete computational checks use local limits
matching existing small-horizon certificate tests, not project-wide options.
The generic source soundness is proved structurally, not by enumeration.

Negative Lean examples include:

1. A forged nonnegative '-objective' constraint yields a valid local zero-bound
   certificate, but source binding and the combined check reject it.
2. A zero-objective certificate is locally valid, but objective binding rejects it.
3. Adding even a zero-weight cross-component implicit term is locally harmless
   to the coefficient identity but rejected by the required empty-term guard.
4. Reordered row tags, a missing constraint and reversed inequality sense fail
   source checks. Equal self-pair zero polynomials do not erase row-tag identity.

Python additionally checks consistently remapped row permutations, asymmetric
coefficient perturbations, wrong sample times, star-gradient cancellation,
all five source blocks, exact tiny fractions, malformed files and CLI behavior.
The new source mirror and weights are compared with the independent old C2/C3A
regression implementations for horizons one through eight.

## Explicit non-claims and next boundary

No live capture or producer/environment authentication; no native leaf-basis
conversion or arbitrary row reordering; no float-to-rational reconstruction;
no general composite primal bundle acceptance or interpolation completeness;
no new actual lower witness, convergence rate, iteration, or error theorem;
no extension to general steps, extended-real h, or stochastic PEP.

The next missing external-pipeline boundary is a genuine native capture and
proved/audited conversion into this centered snapshot, with separate raw and
reconstructed tracks. A centered snapshot by itself does not close that gap.
