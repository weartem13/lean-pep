# v0.12A: actual-function soundness bridge

## Goal

The finite Gram-PEP checker already proves universal upper bounds for any real
datum that realizes a fixed model, has a PSD Gram matrix, satisfies every
ordered interpolation inequality, and meets the formulation assumptions.
v0.12A connects those hypotheses to an actual differentiable smooth convex
function and an actual gradient-descent execution.

This stage does not alter any exact or approximate artifact schema.

## A1: analysis-facing and first-order interfaces — verified

The namespace `LeanPEP.ActualFunction` contains two intentionally separate
contracts.

`IsOneSmoothConvexAnalytic f g` records the standard analysis-facing data on a
real Hilbert space:

- `g x` is the actual gradient of `f` at every `x`;
- `f` is convex on the whole space; and
- `g` is `1`-Lipschitz.

`IsOneSmoothConvexFirstOrder f g` records the exact inequalities consumed by
PEP semantics:

```text
f(x) + <g(x), y - x> <= f(y),

f(y) <= f(x) + <g(x), y - x>
          + 1/2 * <y - x, y - x>.
```

These structures are not definitionally identified.  In particular, the
first-order inequalities are not hidden as extra fields of the analytic
contract.

The A1 files are:

```text
LeanPEP/ActualFunction/Basic.lean
LeanPEP/ActualFunction/Interpolation.lean
tests/lean/smoke/V12A1SmokeTest.lean
```

They were kernel-checked under Lean 4 / mathlib v4.31.0.  The A1 build
completed successfully with 3141 jobs and `tests/lean/smoke/V12A1SmokeTest.lean` passed.

## A2: analytic assumptions imply exact pairwise interpolation — verified

`LeanPEP/ActualFunction/AnalyticBridge.lean` proves:

```text
IsOneSmoothConvexAnalytic f g
  -> IsOneSmoothConvexFirstOrder f g.
```

The lower model is obtained by restricting `f` to the affine line from `x` to
`y` and applying the derivative/slope inequality for a one-dimensional convex
function.  The upper model is the descent lemma: a quadratic remainder along
the same line has nonpositive derivative on `[0,1]`, by the Lipschitz-gradient
bound and Cauchy--Schwarz.

Combining this bridge with the A1 interpolation algebra yields, for every
ordered pair `(x,y)`:

```text
0 <= f(x) - f(y) - <g(y), x - y>
       - 1/2 * <g(x) - g(y), g(x) - g(y)>.
```

The A2 theorem surface includes:

```text
IsOneSmoothConvexAnalytic.lowerModel
IsOneSmoothConvexAnalytic.upperModel
IsOneSmoothConvexAnalytic.toFirstOrder
IsOneSmoothConvexAnalytic.interpolationSlack_nonneg
IsOneSmoothConvexAnalytic.pairwise_interpolation
```

On 2026-08-19, `lake build LeanPEP` completed successfully with 3193 jobs and
`tests/lean/smoke/V12A2SmokeTest.lean` passed under the pinned Lean 4 / mathlib v4.31.0
toolchain.

## A3: finite actual samples realize the Gram model — verified

The verified A3 layer adds two modules.

### Generic finite Gram representation

`LeanPEP/ActualFunction/FiniteGram.lean` defines:

```text
gramOfVectors base i j = <base i, base j>,
realize base u = sum_i u_i * base_i.
```

It proves:

```text
gramInner (gramOfVectors base) u v
  = <realize base u, realize base v>,

IsGramPosSemidef (gramOfVectors base).
```

For a fixed rational `ModelQ`, `dataOfModel` keeps the model's exact symbolic
position and gradient coefficient vectors, fills in the real Gram matrix from
actual ambient vectors, and records actual function values.  A separate
`RealizesActualSamples` proposition states that the symbolic positions denote
centered actual points and the symbolic gradients denote actual gradients.
Under this proposition, every Gram interpolation slack is proved equal to the
corresponding actual-function slack.  Therefore an
`IsOneSmoothConvexAnalytic` function produces `CoreFeasible` finite data.

This is only the soundness direction.  It does not prove interpolation
completeness or construct an actual function from arbitrary feasible finite
data.

### One-step model realization

`LeanPEP/ActualFunction/OneStepGram.lean` instantiates the generic bridge for
`GramPEP.UpperCertificateExamples.oneStepModelQ`.

The actual samples are `(xStar, x0, x1)`, and the ambient Gram basis is:

```text
(x0 - xStar, g(x0), g(x1)).
```

Given:

```text
g(xStar) = 0,
x1 = x0 - g(x0),
< x0 - xStar, x0 - xStar > <= 1,
```

it packages the three exact hypotheses required by the existing certificate
theorem:

```text
RealizesModelQ oneStepModelQ data,
CoreFeasible data,
AssumptionsFeasibleR oneStepModelQ data.
```

`tests/lean/smoke/V12A3SmokeTest.lean` exposes the generic PSD/inner-product bridge and invokes
the complete one-step feasibility package.  On 2026-08-19,
`lake build LeanPEP` completed successfully with 3195 jobs and
`tests/lean/smoke/V12A3SmokeTest.lean` passed under the pinned Lean 4 / mathlib v4.31.0
toolchain.  Thus the exact actual-vector Gram semantics, PSD proof,
`CoreFeasible`, model realization, and radius assumption are kernel-verified.

## A4: one-step actual-function upper theorem — verified

`LeanPEP/ActualFunction/OneStepUpper.lean` applies the already accepted exact
one-step certificate to the A3 datum.  The certificate first gives:

```text
(oneStepData ...).value 2 - (oneStepData ...).value 0 <= 1/6.
```

The final proof step unfolds only the datum's function-value fields and obtains
the actual statement:

```text
actual 1-smooth convex function
+ stationary reference point
+ x1 = x0 - g(x0)
+ ||x0 - xStar||^2 <= 1
-> f(x1) - f(xStar) <= 1/6.
```

The verified theorem surface includes an inner-product-radius form, the
standard norm-squared form, and a corollary with the update substituted
explicitly.  No new certificate, numerical calculation, or completeness
assumption is introduced.  On 2026-08-19, `lake build LeanPEP` completed
successfully with 3196 jobs and `tests/lean/smoke/V12A4SmokeTest.lean` passed under the pinned
Lean 4 / mathlib v4.31.0 toolchain.

This is a universal upper theorem only.  An exact worst-case theorem over the
actual function class additionally requires an actual lower witness or an
interpolation-completeness theorem.
