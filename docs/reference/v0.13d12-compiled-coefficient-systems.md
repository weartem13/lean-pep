## Fixed certificate family

`UpperCoefficientSystem.FamilyQ model q` holds an objective, a residual matrix,
an exact factor payload and q references into the original model assumptions.
q counts ordered occurrences, not distinct constraints. The family has empty
implicit interpolation; it does not mix composite value slots into a single
smooth function. `ofUpperQ seed` extracts these fixed fields. For arbitrary seed
inputs, emptiness of seed.interpTerms must be checked separately; `ofUpperQ` is
not a theorem that deleting implicit interpolation preserves a certificate.
The D12 replay checks this explicitly, and the unchanged D10 compiler refuses
nonempty implicit interpolation before solving.

`instantiateQ f x`, for x : Fin (q+1) -> Q, constructs a certificate whose bound
is x[0] and whose j-th occurrence has weight x[j+1]. It retains references,
objective, residual and factors. The bound has no artificial sign restriction.

The complete equality is

    beta - objective = sum_j weight[j] * assumption[reference[j]] + <S,G>.

The Lean compiler writes it as

    A[i,0] = coefficient_i(const 1)
    A[i,j+1] = -coefficient_i(assumption[reference[j]])
    rhs[i] = coefficient_i(objective) + coefficient_i(<S,G>).

Rows have order: constant, all p function-value entries, then all m*m ORDERED
Gram entries in row-major order, including both (a,b) and (b,a). There are
1+p+m*m rows, including a constant row even when p=m=0. No symmetry or PSD
assumption is used by coefficient extraction or the identity equivalence.

The coefficient function uses Fin.cases, Fin.addCases and finProdFinEquiv. Its
injectivity proof recovers the constant, each value coefficient, and every
ordered Gram coefficient by the existing LinearExprQ extensionality theorem.

`identity_iff_solution` proves, for EVERY x,

    certificateRhsExprQ (instantiateQ f x) = upperTargetExprQ (x 0) f.objective
      iff RationalLinearSystem.IsSolutionQ (compileQ f) x.

`accepted_iff` separately restores the original checker obligations:

    checkUpperCertQ (instantiateQ f x) = true
      iff IsSolutionQ (compileQ f) x
          and all multiplier coordinates are nonnegative
          and PSDFactorValidQ f.residual f.factors.

Thus equality solving alone is not certificate acceptance. No new upper checker
or rate-specific condition is used.

## Binding emitted systems and raw policy boxes

`checkSystemQ f submitted` compares every matrix entry and RHS entry against
`compileQ f`; its soundness theorem gives literal equality of the two systems.
Typed Fin dimensions prevent implicit truncation or padding.

For raw parameter coordinates v and absolute budget eta, `compileBoxQ` uses

    beta in [v[0]-eta, v[0]+eta]
    weight[j] in [max(0,v[j+1]-eta), v[j+1]+eta].

`checkBoxQ` checks the system AND every lower/upper endpoint. `feasible_iff`
connects the box to the original coefficient identity, nonnegativity, and the
coordinate-wise raw budget. With the unchanged PSD factor contract,
`feasible_iff_accepted` identifies box feasibility with accepted fixed-family
certificates satisfying this absolute budget.

`checkRawVectorQ` binds the raw vector to raw.bound followed by ALL raw weights,
while checking the seed/raw reference list correspondence. It preserves lengths,
order, zero entries and repeated references. It does not assert provenance.

The ordinary D8 reduced-denominator condition is NOT a linear box constraint.
It remains an additional, unchanged final policy check. Box infeasibility rules
out even unrestricted rational points in the box, so cannot be repaired by a
stricter denominator constraint. A feasible box point may still fail that
constraint; no complete bounded-denominator search is claimed.

## Transported negative results

`checked_no_identity` / `checked_no_accepted` combine a successful system binding
with an independently checked D10 left-nullspace obstruction. They rule out all
bound/weight assignments for this exact objective/residual/reference family.

`checked_no_identity_in_budget` combines a successful box binding with the D11
Farkas obstruction and rules out every NONNEGATIVE identity within the specified
raw budget, independently of the PSD factor payload. `checked_no_accepted_in_budget`
is the corresponding original-checker consequence. No PSD assumption is needed
for either negative implication.

These conclusions do NOT mean that the PEP is infeasible, that the asserted rate
is false, or that another residual, budget, objective or reference family could
not work. The library defines a fixed empty-interpolation family. The source
model still must pass the established D9/D7-D2 audits before the family can be
identified with the intended algorithmic problem.

## Concrete cases and adversarial checks

The new Lean regression imports, without modifying:

* D11 one/two/three-step bounded examples, with 43x12, 73x22 and 111x36 systems;
* D10's Inconsistent example (43x11), whose fixed residual is PSD but whose full
  coefficient equations admit no bound/weight vector;
* D11's Budget example (43x11), which has valid affine certificates outside the
  allowed raw interval but none in the specified box.

Each emitted system is checked against the Lean compiler. The Budget raw vector
and box endpoints are separately bound. The negative conclusions now concern
fixed-family certificates, not just unconnected SystemQ/BoxQ values.

A forged system with zero A and a nonzero RHS has a perfectly valid checked
obstruction. `forged_local_obstruction_check` verifies it; `forged_system_rejected`
then rejects its attempted binding to the original family. Other tests modify an
ordered (1,0) Gram row, the raw bound coordinate, or one lower endpoint. No test
repairs these bad inputs or alters a checker to accept them.

The empty-value/empty-Gram example proves that the constant row remains and that
a negative bound can be valid for a negative constant objective. It does not
add a nonnegative-bound precondition.

## Replay commands

After applying the patch, run the project and new smoke:

    lake build LeanPEP && lake env lean tests/lean/smoke/V13D12SmokeTest.lean

The new tool calls the UNMODIFIED old solver pipeline, preserves every old output,
and adds a separate compiler report and `BindingReplay.lean`.

Positive bounded example:

    python3 tools/audit_compiled_completion.py \
      data/fixtures/pepit_bounded/pg_three.json --mode box --expected-steps 3 \
      --output-dir /tmp/pg-d12-three --namespace LeanPEP.Imported.PGD12Three
    lake env lean /tmp/pg-d12-three/BindingReplay.lean

Bounded negative example:

    python3 tools/audit_compiled_completion.py \
      data/fixtures/pepit_bounded/pg_budget.json --mode box --expected-steps 1 \
      --output-dir /tmp/pg-d12-budget --namespace LeanPEP.Imported.PGD12Budget
    lake env lean /tmp/pg-d12-budget/BindingReplay.lean

Linear negative example:

    python3 tools/audit_compiled_completion.py \
      data/fixtures/pepit_completion/pg_inconsistent.json --mode linear --expected-steps 1 \
      --output-dir /tmp/pg-d12-linear --namespace LeanPEP.Imported.PGD12Linear
    lake env lean /tmp/pg-d12-linear/BindingReplay.lean

The output directory must be new or empty. Exit 0 means the Python binding
diagnostic succeeded; it does NOT mean the candidate is feasible or Lean-checked.
Read previous_status and previous_completion_accepted in the report. Infeasible
cases contain a negative certificate-family conclusion, not an actual_upper
assertion. A pivot limit has no infeasibility conclusion. Binding failure adds
no transported D12 theorem. All reports retain lean_checked=false.

The positive replay preserves the original D10 actual-function theorem, using
its original full checkCompletedQ acceptance. The new compiled-family check is
additional and cannot replace source/trace/denominator audits. No rate changes.
