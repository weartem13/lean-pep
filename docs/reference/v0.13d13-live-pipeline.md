## First real run

Use the existing optional dependencies, separate from the Lean environment:

```bash
python3 -m venv .venv-pepit
.venv-pepit/bin/python -m pip install -r requirements-pepit-capture.txt
.venv-pepit/bin/python tools/run_pepit_pipeline.py live \
  --steps 1 --solver CLARABEL \
  --output-dir /tmp/leanpep-d13-live-one \
  --namespace LeanPEP.Imported.Live.PGOne
```

The output directory must be absent or empty. A new directory is required for
another run; nothing is silently removed, reused or overwritten. No installation
or upgrade is performed by the runner. Its normal mode runs `lake build LeanPEP`
and the generated `Replay.lean` automatically. Existing mathlib/Lean pins remain.

The existing reconstruction defaults are retained (denominator bound 1000000,
absolute change 0.000001). They are not guaranteed to recover a certificate.
`--max-denominator`, `--max-abs-error`, `--max-pivots`, and `--solver-options`
allow an explicitly different new run, recorded in its artifacts. Source
coefficients never enter reconstruction. The reported accepted bound is the
selected candidate's own exact value, not an injected `1/4`.

`--prepare-only` snapshots and audits the real symbolic model without solving;
it needs PEPit and its import dependencies, but does not require the selected numerical solver. `--skip-lean` explicitly
stops at candidate preparation and never claims kernel verification.

## What happens

1. Record the actual Python/package versions and PEPit source-file hashes.
   These are reproducibility observations, not authentication or formal proof.
2. Prepare the actual pinned PEPit objects, save `prepared_capture.json`, and
   run the old source audit BEFORE the numerical solve. A rejected source stops
   the run, retaining the rejected snapshot.
3. Solve without dimension reduction. Preserve all multipliers (including zero
   and negative values), the independent residual, bound, and original ordering.
   Verify that prepared/sent object order and symbolic data did not change.
4. Save `capture.json` before attempting the primal sidecar. Snapshot raw wrapper
   G/F into `primal_observation.json`; do not call `Point.eval()` to reconstruct G.
5. Run old D9/D8/D7–D2 diagnostics. Select raw if independently accepted, otherwise
   reconstructed if independently accepted. Only otherwise invoke unchanged
   D11 bounded completion and D12 compiler binding. No new solver or checker is
   introduced by this orchestration layer; the seed residual remains fixed.
6. Generate `Replay.lean` with the selected old actual-function theorem. A bound
   B yields `F(x_T)-F(x_*) <= L R^2 B`. For a bound obstruction, no positive actual
   upper is inserted. A successful negative replay is not a positive certificate.
7. Run build and replay, retain both logs, and require the explicit actual_upper
   axiom output with dependencies contained in propext/Classical.choice/Quot.sound
   before recording a positive upper as verified. Missing output does not pass.

The Lean parser, compiler, actual source/certificate check and the generated proof
remain decisive. Python dispatch decisions, source hashes and reports carry no
independent theorem-level authority.

## Outputs and status

- `environment.json`: actual versions, source hashes, solver availability.
- `prepared_capture.json`, `prepared_audit/`: pre-solve symbolic source.
- `capture.json`, `capture.log`: actual capture and solve log. In replay mode the
  input bytes are copied exactly; no policy override is applied to the archive.
- `primal_observation.json`: raw G/F in their native orders, including tau. This
  is a numerical observation, NOT a certified finite or actual primal witness.
- `audit/`: old raw/reconstructed artifacts and diagnostics, all retained.
- `completion/`: old D11/D12 outputs only when completion was needed.
- `selected_exact.json`: only written for a selected accepted candidate.
- `Replay.lean`, `lean_build.log`, `lean_replay.log`: proof candidate and actual
  proof execution results when executed.
- `pipeline_report.json`: distinct source, candidate, Lean, and invocation states.
  On failures the available artifacts survive; detailed exceptions use `error.log`.

Exit codes: 0 = the requested mode completed (positive proof in normal numeric
mode; only candidate preparation with --skip-lean; only symbolic audit with
--prepare-only). 1 = runtime/input/execution failure. 2 = source rejection or
no accepted positive candidate (including a valid negative obstruction).
3 = positive candidate ready but Lean unavailable/failed.

Therefore exit 0 by itself never establishes D13. Check all of:

```text
live_capture_performed = true
candidate_accepted = true
actual_upper_verified = true
d13_acceptance_met = true
```

The last flag refers conservatively to THIS invocation. Replay never claims it
performed a live solve, even if an archive's producer metadata says "live".
A genuine archived capture and its later checked replay can be documented as
separate pieces of evidence, without rewriting either run's status.

## Replay an archive

```bash
python3 tools/run_pepit_pipeline.py replay \
  /tmp/leanpep-d13-live-one/capture.json \
  --steps 1 --output-dir /tmp/leanpep-d13-replay-one \
  --namespace LeanPEP.Imported.Replay.PGOne
```

Replay requires no PEPit/solver package. It uses the archive's policy and does not
alter or delete the original file. To exercise the integration offline with old
regression input, replace the input with `data/fixtures/pepit_capture/pg_one.json` and
use a different output directory. That source remains **simulated_regression**.

## Scope retained

One supported unit-PG profile, explicit source semantics, all existing exact
checks. No new convergence rate, no assertion that recovery must succeed, no
primal feasibility proof, no interpolation completeness, no general residual
search. A fixed-family obstruction does not mean the original PEP is infeasible.
No temporary absence of local tools is used to downgrade D12's user-verified state.
