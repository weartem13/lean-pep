# v0.13D4 — exact composite storage-order audit

## Status and baseline

D4 passed the user's local `lake build LeanPEP` (3330 jobs) and complete
`tests/lean/smoke/V13D4SmokeTest.lean` on 23 September 2026. The eight reported axiom checks
contain only subsets of propext, Classical.choice, and Quot.sound. This status
is supported by the user's log, not by running Lean in the authoring container.
D4 does not claim a new convergence rate.

## Scope

The source is an exact normalized positive-horizon PG snapshot with the same
leaf set as D3, but five independent storage orders can vary: native basis,
function values, smooth samples, nonsmooth samples, and constraint rows.
T=n+1>0, p=2T+3 value slots, b=2T+4 native basis vectors, T+2 smooth samples,
T+1 nonsmooth samples, and (T+2)^2+(T+1)^2+1 explicit rows. All typed arrays use
these exact sizes. No row is silently omitted, duplicated, sorted, or rescaled.
Extra or missing array entries are rejected by the external parser; the Lean
payload encodes fixed-size arrays directly, not defaulted list lookups.

For each axis, `toSource[canonical] = source` gathers coefficients; its inverse
`toCanonical[source] = canonical` transports references. Both inverse equations
are checked over every Fin index before the arrays are used as a bijection.
An in-range but nonbijective array is still a Lean-representable candidate,
which must fail the check. The Python parser does not repair its inverse.

Row-tag i/j are LOGICAL point identifiers in the original component convention,
not offsets into the permuted smooth/nonsmooth sample arrays. Row tags move with
their constraint rows. The two sample arrays are never merged; values may be
interleaved globally. The header's coordinate string names the canonical family;
the supplied ordered labels name the actual storage order.

## Lean layer

`GramPEP.ExactReindexing` constructs an Equiv only from checked inverse arrays,
proves vector/matrix/expression/sample round trips, transports rank-one factors,
and proves full real expression evaluation invariance by reindexing finite sums.
No PSD or symmetry hypothesis is needed for that scalar identity: both matrix
cross blocks are present. This is permutation-only; it is not origin elimination.

`Adapters.ProximalGradientOrdering` reconstructs D3's native order from the
SUBMITTED payload. Center-matrix columns and section-matrix rows move with the
native basis; their centered axis stays fixed. The full Snapshot round-trip
includes all metadata, labels, samples, rows, matrices and the objective.
The source acceptance theorem characterizes acceptance by valid inverse arrays
and exact equality of the restored native snapshot with D3.expectedSourceQ.

The upper certificate keeps its bound and all terms/weights. Value references
and assumption-row references use the inverse direction. The source certificate
is checked by the old checkUpperCertQ. The reordered certificate then passes
D3's old checkBoundQ, which also checks its centered restriction through D2.
The empty-implicit-interpolation and objective-binding guards remain explicit;
zero-weight implicit terms are not discarded. This conservative implementation
does NOT prove or assume that arbitrary locally accepted certificates remain
accepted without the second independent check.

`ActualFunction.ProximalGradientOrderingAudit` calls the unchanged D3 actual
function theorem, giving LR^2 * c.bound for arbitrary n. The concrete three-step
example has bound 1/12. No new actual lower witness or tightness is constructed.

## Tests and inputs

Four committed deterministic inputs: permuted T=1,2,3 and identity-order T=1.
They start from D3's existing independent exact inputs and D1 factors; no solver
is called. Normal regeneration reads these files and NEVER recreates them.
The supplied rotations include non-involutions, so using the wrong permutation
direction cannot accidentally pass every test.

Independent Lean regression scripts check each positive candidate, a malformed
unused inverse, wrong labels, incorrect multiplier row references, a zero-weight
implicit term, and a locally valid zero-bound certificate of a forged problem.
The generated data module contains no acceptance theorem.

The 39 Python tests also cover all permutations through size 5 (including the
empty size), arbitrary nonsymmetric expression/data matrices, source/upper round
trips, D3/D2 command chaining, invalid JSON and arrays, and hidden origin terms.
These tests do not execute Classical.choose, validate Lean elaboration, establish
producer identity, or prove a parser-to-typed-payload correspondence.

    git apply LeanPEP_v0.13D4.patch
    lake build LeanPEP
    lake env lean tests/lean/smoke/V13D4SmokeTest.lean

Only apply to D3 Fix 1. The unchanged precise source/coordinate checks remain
reachable from the aggregate; no module is removed to obtain a build.

## Not included

No live PEPit capture; no automatic leaf/order inference; no elimination of
additional dependent leaves; no row rescaling, epigraph/redundant-row deletion,
arbitrary dense change of basis, or extra constraints. Row tags with storage
sample offsets must be translated by a separate future audited interface.
No decimal/float reconstruction, producer authentication, native primal input,
or generic primal-to-actual interpolation completeness. The generic dataR
permutation lemma is NOT a native primal-import implementation.
