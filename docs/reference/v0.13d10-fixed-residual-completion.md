## Three distinct endpoints

The input is the unchanged D9 capture format. The raw decimal interpretation is
retained unchanged. The unchanged D8 entrywise bounded-denominator procedure
produces a second endpoint, called the seed here (`reconstructedUpperQ` in the
reused data renderer). D10 proposes a third endpoint, `completedUpperQ`.

Only the completed **bound and existing assumption weights** may differ from
the seed. Objective, independent residual matrix, factor payload, source,
reference indices, term counts, ordering, and empty interpolation remain fixed.
In particular, D10 does not reconstruct a matrix from the completed weights.

The residual frozen by D10 is the D8 **seed** residual, not necessarily the raw
decimal matrix. The raw-to-seed change remains explicitly governed by D8's
policy and is not erased by this terminology. Factors were produced by D1
for that seed matrix; D10 retains them and checks them again in the final
certificate. Factor denominators are not numerical reconstruction parameters.

## Exact coefficient equations

For the fixed model, objective `o`, residual `S`, and original assumption
reference list `j_1,...,j_q`, solve for

    x = (bound, lambda_1, ..., lambda_q).

The equations are all coefficients of

    bound - o = sum_t lambda_t * model.assumptions[j_t] + <S,G>.

Coefficient order is constant, all value slots (including tau), and ALL
ordered Gram entries in row-major order. Both off-diagonal entries are kept;
no symmetric reduction, PSD projection, diagonal perturbation, or zero
threshold is applied. The compiler uses the source rows after their stated
orientation to >=0, not the printed <=0 expressions with incorrect signs.

The first column of A is the constant-expression unit vector. Each following
column is minus the complete coefficients of the corresponding oriented row.
The right-hand side is the complete coefficient vector of `o + <S,G>`.
The captured bound is a seed coordinate, NOT a lookup key for a known rate.

Gauss--Jordan elimination uses only Fraction arithmetic, deterministic pivot
selection, and original input rows. A consistent system gets a solution by
keeping all free variables equal to their seed values and determining pivot
variables exactly. An inconsistent system gets a rational row combination y:

    y^T A = 0,       y^T b != 0.

Every result is independently recomputed against the entire original system.
There is no clipping of a negative multiplier. Linear consistency alone does
not check multiplier nonnegativity, PSD, denominator limits, source validity,
or the original certificate. Those remain independent acceptance conditions.

## Lean and trust boundaries

`RationalLinearSystem` provides `checkSolutionQ`, `checkObstructionQ`, their
exact proposition-level meanings, and `checked_obstruction`. Its proof uses
finite-sum rearrangement to derive y^T b = y^T A x = 0 from a hypothetical
solution. Empty row/column dimensions are allowed.

The row-reduction algorithm is not trusted. The Python source-to-system
compiler has NOT been proved correct in Lean in this release. A checked
obstruction therefore certifies the emitted exact system. It is not a proof
that the original PEP is infeasible, that another residual cannot work, or
that a rate is false. On the positive path, this compiler is not a soundness
assumption: the final candidate is checked independently against the original
model by the old full certificate checker.

`ProximalGradientCompletion.checkCompletedQ` requires:

1. the seed respects the original raw-to-seed D8 policy;
2. seed and final have identical objective, residual, factor signature and
   ordered references, and both have empty implicit interpolation;
3. the final candidate passes unchanged D9 trace binding, raw binding, D8
   raw-to-final policy and D7--D2 source/upper checks.

The final error bound is measured DIRECTLY from raw, never by adding two
allowed stagewise error budgets. There is no requirement that raw or seed
already be a valid certificate. `completion_within_raw_policy` states the
final comparison, and `residual_preserved` states the frozen seed matrix.
The target signature compares every factor weight and every vector entry,
not just a hash or reconstructed matrix value.

The source, trace, and certificate objects are submitted typed values. Producer
identity, JSON parser correctness, original bytes, package versions, and
nearest-rational or nearest-solution optimality are not kernel-authenticated.

## Actual-function theorem

The new actual-function module simply calls unchanged D9. After joint
acceptance it proves

    F(x_T)-F(x_star) <= L * R^2 * completed.bound.

It preserves the existing smooth-convex, ordinary minimizer, actual run and
radius hypotheses. No extra eta term is needed: the completed certificate is
itself required to be exactly valid. `three_step_upper` recovers LR^2/12 for
the simulated three-step example; it is not a new rate or a new tightness
result. Raw acceptance is never inherited from completed acceptance.

## Commands

Apply the increment to a D9 project, then run:

```bash
lake build LeanPEP && lake env lean tests/lean/smoke/V13D10SmokeTest.lean
```

Complete a stored D9-format capture (no PEPit/solver dependency):

```bash
python3 tools/complete_pepit_proximal_gradient_capture.py \
  data/fixtures/pepit_completion/pg_three.json \
  --expected-steps 3 \
  --output-dir /tmp/pg-d10-three \
  --namespace LeanPEP.Imported.PGD10Replay \
  --require-completed-pass
```

The output directory must be absent or empty. Existing files are not deleted
or silently reused. This prevents stale successful artifacts from surviving
a later failed completion. Exit 0 means the requested Python diagnostic
succeeded; exit 2 with `--require-completed-pass` means it did not. It does NOT
mean Lean ran. Failure evidence is written before exit 2.

Outputs retain the original capture, immutable raw, seed and optional completed
exact candidate, exact linear system/result, and a detailed report with
`lean_checked=false`. `Replay.lean` is self-contained after the project has
been built:

```bash
lake env lean /tmp/pg-d10-three/Replay.lean
```

For an accepted candidate, it proves a linear solution check, the full D10
acceptance check and an actual-function upper theorem using the submitted
completed bound, then prints axiom dependencies. For an inconsistent system it
instead proves the obstruction and no-solution result; no positive upper
statement is emitted. For a consistent but rejected candidate it emits a
rejection check. These generated replay scripts were NOT executed in the
current authoring environment.

D9's existing optional capture command may produce an input for this tool in a
configured environment. D10 does not make that live run a fact. The complete
fallback remains explicitly conditional on actual capture and final Lean
acceptance.

## Not covered

No automatic successful reconstruction guarantee, inequality-constrained choice
of free variables, nearest completion, modification of the seed matrix,
nullspace/kernel recovery, live solver result, native primal import, general
interpolation completeness, or new worst-case value is claimed. If the fixed
seed residual is incompatible, D10 returns evidence and stops rather than
changing the matrix to manufacture a successful certificate.
