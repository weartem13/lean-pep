## Scope and precise conventions

The complete D4 stored snapshot, five bidirectional order maps, sample arrays,
value slots, row labels, rectangular origin maps and objective are retained.
T=n+1>0. There is one rule per SOURCE-STORAGE row, before D4 permutes any index.
A rule contains a sense (geZero or leZero) and a strictly positive rational scale.
The raw polynomial q denotes q>=0 or q<=0, respectively. There are no equality
rows, strict inequalities, two-sided rows, hidden offsets, or additional rows.
All affine constants and all entries of both Gram axes are part of q.

orient(q) = q for geZero; orient(q) = -q for leZero.
normalized(q) = orient(q)/alpha, alpha > 0.
encode(e) = orient(alpha*e).

The existing checker ALWAYS receives a model with oriented >=0 assumptions.
A submitted upper multiplier lambda is nonnegative on this oriented row. Thus
mu = lambda*alpha is its multiplier on the normalized row. In the REVERSE
fixture-construction direction, lambda = mu/alpha. Sign is NOT folded into the
nonnegative multiplier. The JSON field multiplier_convention must be exactly
nonnegative_on_oriented_rows_v1. Raw signed duals from an unspecified solver
are unsupported, not silently converted.

The header sense remains the D4 internal geZero convention; per-row raw senses
are separate data. Logical i/j labels remain logical component-point identifiers,
not source array offsets. Scale lookup uses the source row index before D4's
row inverse is applied. Objective normalization is not part of this stage.

## Formal content

RowNormalization.lean defines the local operations and proofs of both inverse
identities for nonzero scales, injectivity, pointwise real feasibility equivalence
for positive scales, and weighted-expression preservation. It does not assume
PSD, symmetric Gram data, convexity, or a particular witness for the algebra.

ProximalGradientRows.lean uses the existing D4 snapshot type. Its source model
contains the actual oriented submitted rows, not a pre-filled expected model.
The normalized source divides those rows, retaining all other snapshot fields.
Source acceptance checks every scale's strict positivity and then uses D4's
unchanged source audit; D4 passes to D3 and D2's original independent compiler.
The complete raw snapshot is recovered by re-encoding its normalization.

The adapter proves an equality of the full symbolic weighted assumption sums,
then of the certificate right-hand sides (with empty implicit interpolation).
normalizedUpper_check proves: positive rules + original accepted upper certificate
+ empty implicit interpolation -> acceptance of the deterministically normalized
certificate by the SAME original checkUpperCertQ. This is an actual preservation
proof script for this stage, not just a finite test or a new checker.

The boundary still rechecks both representations and retains the original
source binding, target equality, nonnegative multiplier/PSD/identity checks,
and empty implicit interpolation guard. No zero-weight term or duplicate term
is dropped. The bound, objective, dual matrix and factors are unchanged.

ProximalGradientRowAudit.lean directly calls D4's existing finite and actual
function bridges. For every positive horizon, acceptance yields
F(x_T)-F(x_star) <= L*R^2*c.bound under the original actual smooth-convex,
convex h, minimizer, exact prox run, positive L and radius hypotheses.
The three-step input has c.bound=1/12. This is not a new rate/tightness result.

## Input tool

python3 tools/import_proximal_gradient_rows.py \
  data/fixtures/composite_rows/pg_three.json --expected-steps 3 \
  --lean /tmp/PGThreeRows.lean --report /tmp/PGThreeRows_report.json \
  --normalized-json /tmp/PGThreeRows_normalized.json \
  --namespace LeanPEP.Imported.PGThreeRows

The output JSON is accepted by the unmodified D4 importer. Its output may then
be passed to the unmodified D3 and D2 importers. Generated Lean contains literal
submitted polynomials, rules, order maps and certificate data; independent
acceptance proofs are in CompositeRowsRegression.lean.

Exact numbers use {num,den}, never floats or decimal strings. Lengths, indices,
unknown fields, duplicate keys and the explicit multiplier convention are checked.
Zero/negative rational scales remain representable for independent rejection.
Normalization at zero follows Lean's total field inverse (inverse zero is zero);
the strict-positive guard still rejects it. No candidate is repaired. By default
format-valid, mathematically rejected candidates can be emitted with failed
diagnostics; --require-diagnostic-pass makes that exit with code 2.

## Regression fixtures and limitations

Four deterministic exact fixtures: mixed senses/scales for T=1,2,3 on nontrivial
D4 permutations, and unit scales/geZero on D4's identity one-step fixture.
Input creation reuses old exact data and factors without any solver call. Normal
regeneration reads committed inputs only and never replaces them with expected
constraints. The new 39 Python tests cover exact arithmetic, both multiplier
transform directions, source-vs-canonical lookup, all coefficients, four-layer CLI
replay, and deliberate failures. Lean smoke has 32 checks, 13 examples and eight
axiom queries, all pending execution in the authoring environment.

Important negative tests include zero and negative scales on a zero self-pair:
the normalized D4 source can still pass, but the D5 scale guard rejects them.
Other tests preserve wrong-sense/nonzero-row rejection, wrong positive scale,
wrong multiplier updates, zero-weight cross-component interpolation, hidden
origin pollution, bad inverse maps and a locally valid certificate of a forged
problem. Rejection is of a submitted candidate/contract, not a claim that a
separately stated optimization theorem is false.

No live PEPit capture, automatic scale/sign/order inference, equalities,
redundant/epigraph rows, dependent leaf elimination, objective scaling,
floating-point reconstruction, native primal import, producer authentication,
or interpolation completeness is added. Typed-snapshot mathematical checking
does not prove JSON parser byte correctness or external origin identity.
