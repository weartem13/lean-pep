## Mathematical boundary

T=n+1>0, with the SAME D5 signed/scaled source in its external storage order.
There is ONE additional scalar value tau at index 0 and ONE performance row
at index 0. Old scalar value i and row j are shifted to i+1 and j+1. The old
Gram basis, rectangular origin maps, two function components, point tags and
five ordering maps are unchanged. The auxiliary variable is not a sample of
f or h, and is not a new Gram vector.

Write o for the base source objective. The maximized objective is tau and the
new inequality is tau <= o. In >=0 orientation its expression is gamma*(o-tau),
where gamma is strictly positive. It can be encoded in either D5 raw sense
(geZero or leZero). This is a hypograph constraint for a maximization problem;
we do not reverse it to o <= tau. The input multiplier convention is the same
explicit nonnegative-on-oriented-rows convention as D5.

A real feasible base datum can be extended with ANY tau <= o(d). In particular,
choosing tau=o(d) preserves feasibility and attains the same performance value.
This choice is not an equality imposed on every feasible extended datum.
The module proves equality of all scalar upper-bound statements, without
assuming nonemptiness, attainment, compactness or a known optimal value.

## Generic affine substitution

PerformanceLift.lean adds the scalar slot, retains the tail expression, and
substitutes tau=o. If e has auxiliary coefficient a then

  substitute(o,e) = tail(e) + a*o.

It keeps the constant, every value coefficient, and both axes of every Gram
coefficient. The real evaluation identity is proved for arbitrary data, not
only PSD/symmetric matrices or matching lower witnesses. The general helper
allows the metric o itself to have constant and Gram terms. D5 still binds the
actual application metric to the old proximal-gradient objective.

The support DataR's position/gradient fields at the artificial slot are zeros
only as irrelevant carrier fields: implicit interpolation MUST be empty. No
smooth interpolation is asserted involving tau.

## Independent source and certificate guards

SourceQ contains the complete submitted D5 base source, performance rule,
ACTUAL extended raw row array and ACTUAL extended objective. checkLiftQ checks
strict positivity of gamma, EVERY extended row against its explicit lifting,
and the objective against tau. checkSourceQ additionally invokes the unchanged
D5 source checker. We do not fill in missing extended rows from the expected
model before checking. The input raw rows and source objective remain literal
in generated Lean.

Both the original extended certificate and its eliminated certificate are
checked. checkBoundQ retains empty implicit interpolation and objective binding,
and invokes the entire original D5/D4/D3/D2 bound path after elimination.

The elimination substitutes the complete certificate expression, removes ONLY
references to the declared performance row, subtracts ONE from retained source
row indices, and leaves the following unchanged:

- bound;
- dual matrix and exact PSD factors, with all factor weights;
- each retained assumption multiplier and the relative term order;
- zero-weight and duplicate BASE-row references;
- the base source and all its ordering/rule/sample metadata.

D5 scale lookup and D4 inverse reindexing happen AFTER this offset is removed.
There is no new factor synthesis, rounding, objective rescaling or known-rate
replacement at this stage.

assumption_sum_preserved and certificate_rhs_preserved prove exact coefficient
identities. eliminatedUpper_check proves that a valid lifting, an accepted raw
upper, and EMPTY implicit interpolation imply acceptance of the eliminated
upper by the SAME original checker. It does not assume an accepted base upper.

The total candidate function eliminatedUpperQ has empty implicit interpolation
because there is no supported meaning for interpolation on tau. Its soundness
theorem REQUIRES the original list to be empty; the joint guard checks it even
for zero-weight terms. The CLI refuses --base-json output for nonempty implicit
input rather than silently exporting a cleaned certificate.

## The performance-row multiplier is derived, not guessed

The base rows and dual pairing have zero tau coefficient. Comparing that
coefficient in the FULL accepted raw identity therefore gives

  gamma * (sum of multipliers referencing the performance row) = 1.

performance_mass_eq_one proves precisely this statement. Duplicate references
are allowed. No single multiplier is forced to one, no dual is overwritten,
and no approximate numerical equality is accepted. For gamma=2/3, one reference
has multiplier 3/2. The two-step sample splits its mass into TWO nonzero
references separated by base terms; only their total weighted mass equals one.

## Applications and negative evidence

ProximalGradientPerformanceAudit.lean invokes the unchanged D5 actual-function
bridge. The universal target remains

  F(x_(n+1))-F(xStar) <= L*R^2*c.bound,

with the existing actual smooth-convex, real-valued convex nonsmooth, positive L,
minimizer, exact prox-run and radius hypotheses. three_step_upper uses the new
three-step source data with bound 1/12. This is not a new rate or tightness claim.

Four deterministic exact fixtures (T=1,2,3 and one-step unit conventions) retain
D5's nontrivial order, raw row senses and scales. Normal regeneration reads the
committed input files only; --create-fixtures is a separate explicit operation.
All fixtures are clearly marked NOT live solver capture.

Negative tests include:

- adding a multiple of o-tau to a base row: it vanishes on substitution, but
  the ORIGINAL extended-source comparison rejects it;
- doubling the performance multiplier: the eliminated old bound still passes,
  but the raw identity and joint bound check reject it;
- a locally accepted certificate of a forged performance metric;
- reversed sense, wrong/zero/negative scale, zero objective, and zero-weight
  implicit interpolation involving the auxiliary scalar;
- missing/extra rows, value-dimension errors, a fictitious extra Gram coordinate,
  out-of-range indices, duplicate/unknown JSON fields and non-rational input.

The scalar-layout and strict JSON checks do not prove JSON parser correctness
or authenticate a producer. Lean certifies the generated typed mathematical
snapshot. Hashes and origin labels are documentary only.

## Exclusions

No live PEPit run, floating-point reconstruction, raw IEEE bit interpretation,
raw signed solver dual conversion, inferred auxiliary placement, multiple
performance metrics/max-min elimination, equality constraints, omitted self
rows, arbitrary redundant/epigraph rows, native primal import or interpolation
completeness. The single auxiliary layout is explicit, not advertised as all
PEPit storage conventions. The existing exact worst-case results remain intact.
